

## Application Overview

This application is designed to manage and process scientific experiments related to lie detection. It is divided into two main components:

1. **Experiment Module (MVC - Model View Controller):**  
   This part of the application is built using the MVC design pattern, with the following specific components:
   - **Model (Lie_Detection_Protocol_Model):** Contains the business logic, data structures, and interactions with the data layer.
   - **View (Lie_Detection_Protocol_View):** Manages the user interface and displays the data to the user.
   - **Controller (Lie_Detection_Protocol_Controller):** Handles user inputs, updates the model, and manages the flow of the application.

   The Experiment Module is responsible for running lie detection experiments, collecting data, and saving the results. The collected data is saved in `.xdf` format via an LSL (Lab Streaming Layer) server. During the experiment, markers are sent to the LSL server to indicate key events. There are three types of markers:
   - **lie:** Indicates when a participant is lying.
   - **true:** Indicates when a participant is telling the truth.
   - **start:** Marks the beginning of the experiment or a specific trial.

   Additionally, a script named `xdf2fif` is provided to convert these `.xdf` files into `.fif` format for further processing.

2. **Data Processing Module (Data_Processing):**  
   This module processes the converted `.fif` files generated by the `xdf2fif` script. It retrieves these `.fif` files and performs various processing tasks. The module is organized into three main classes:

   - **Preprocessing:**  
     This class is responsible for extracting raw data from the `.fif` files and organizing it into epochs, which are segments of data corresponding to specific events (e.g., lie, true). It prepares the data for further analysis by filtering, normalizing, and handling artifacts.

   - **Classifier:**  
     The Classifier class extracts both temporal and frequency features from the preprocessed data. It then uses these features to classify the data using machine learning models such as Random Forest and Support Vector Machines (SVM).

   - **Processing:**  
     The Processing class is responsible for final data analysis and visualization. For example, it includes methods for source localization of brain activity, enabling visualization of brain regions activated during different stages of the experiment.

## Future Development

Given the current architecture, it would be relatively straightforward to create an online version of this application. In future iterations, the **Classifier** could be integrated directly with the **Experiment Module** to provide real-time feedback. This enhancement would allow the system to instantly detect and report whether the participant is lying or telling the truth during the experiment.

## Project Structure

- **Lie_Detection_Protocol_Model:** Contains the business logic and data structures for the experiment.
- **Lie_Detection_Protocol_View:** Handles the user interface and data presentation.
- **Lie_Detection_Protocol_Controller:** Manages the interactions between the Model and View components.
- **Data_Processing:** Contains scripts and tools for processing and analyzing experiment data.
  - **Preprocessing:** Class for data extraction and preparation.
  - **Classifier:** Class for feature extraction and data classification.
  - **Processing:** Class for final data analysis and visualization.
- **Lie_Detection_Protocol.py:** The main entry point of the application.
- **xdf2fif.py:** A script to convert `.xdf` files to `.fif` format.
